# @delthin/dsh-tool-wrap

[English](<README.en.md>) | [变更日志](<CHANGELOG.md>)

`@delthin/dsh-tool-wrap` 是面向 DeepSeek Harness（DSH）`>= 0.2.2-rc.1` PTC 会话的工具按需发现插件。插件根据工具实际注册来源生成目录、选择项和发现概览，在兼容的 PTC SDK 提示词中将所选插件精简为模块简介与工具名称列表，并在模型调用 `unwrap` 时按精确插件 ID 返回调用者可见的原始工具定义。

插件默认关闭。原生工具调用模式、关闭状态以及不兼容的 SDK 组装路径均保留宿主原有展示。

## 功能概览

- **按插件精简 PTC SDK 展示**：启用后，从 `tools:sdk` 延后所选工具的完整参数与返回值定义；独立 unwrap 目录保留插件 ID、简介及全部工具名称。
- **按精确 ID 整包发现**：模型在 `run_code` 中调用 `unwrap`，按精确插件 ID（或未识别来源工具的精确工具名）读取当前调用者可见的完整工具定义。发现过程不提供关键词搜索，不直接执行目标工具，也不扩张调用权限。
- **灵活的范围控制**：支持按插件（`groups`）整包纳入、按工具名（`tools`）显式纳入，以及按工具名（`exclude`）优先排除。选中整个插件后，该插件后续新增的工具会自动纳入按需发现范围；被排除的工具始终保持完整定义展示。
- **插件简介管理**：优先读取插件包自带的开发者说明，支持为每个插件保存自定义简介（1–2000 字符），或调用当前部署默认模型根据插件全局工具名与描述生成简介草稿。
- **平滑迁移与原子落盘**：自动将历史 `v1`、`v2` 配置升级为 `v3` 结构，通过同目录临时文件原子重命名（权限 `0600`）写入当前 profile 的 `tool-discovery.json`。

### 版本测试与兼容说明

- **契约依赖**：DSH `0.2.2-rc.1` 将 `renderToolsSdk` 与 `renderToolsSdkPy` 移至 `@deepseek-ai/dsh-tool-executor-ptc`，移除了旧版 `tools.modeFor`，并引入按调用步骤解析的条件工具集合。本插件基于上述新版契约实现，不支持 `0.2.2-rc.1` 之前的宿主版本。
- **适配基线**：独立宿主资产针对 `cordis 4.1.0` + `DSH 0.2.2-rc.1` 的已审核文件形态，激活与服务验收由宿主维护者在授权窗口执行。
- **开放上限说明**：依赖范围采用开放上限（`>=`）以便在后续小版本中安装，但开放范围不代表对未来尚未发布的宿主破坏性 API 变更提供事前保证。

## 安装与从旧包迁移

### 安装与宿主接入

通过 npm 安装（或按宿主支持的本地包/bundle 导入方式接入 DSH）：

```bash
npm install @delthin/dsh-tool-wrap
```

从源码仓库执行依赖安装、静态检查与打包：

```bash
npm ci --ignore-scripts
npm run check
npm pack --workspace @delthin/dsh-tool-wrap
```

请按照当前 DSH 宿主环境支持的插件 bundle 导入或启动门控挂载方式加载 `@delthin/dsh-tool-wrap/origin-bootstrap` 与 `@delthin/dsh-tool-wrap` 主插件，并在安装或更新后重启 DSH 服务。

### 从 `dsh-tool-discovery` 升级注意事项

本包由原本地包名 `dsh-tool-discovery` 迁移而来。模型工具正式名称现为 `unwrap`，旧会话的 `discover_tools` 保留兼容调用但不出现在新普通 PTC 提示词中；服务名、页面路由 ID 以及 profile 配置文件名（`tool-discovery.json`）保持不变，客户端、图标与多语言（locale）导出均已收敛至 `@delthin/dsh-tool-wrap` 命名空间下。

升级时请严格遵循以下步骤：

1. **避免新旧实例同时启用**：由于新旧包共享相同的内部服务名、工具名与页面 ID，切勿在同一宿主实例中同时加载或启用 `dsh-tool-discovery` 与 `@delthin/dsh-tool-wrap`。
2. **备份并沿用原配置**：升级前请先备份当前 profile 目录下的 `tool-discovery.json`。新包可直接读取并沿用原配置文件，首次加载或保存时会自动迁移至 `version: 3`。
3. **移除旧包并重启服务**：请按照你当前宿主环境的实际管理方式停用并移除旧版 `dsh-tool-discovery` 插件及启动挂载，接入 `@delthin/dsh-tool-wrap` 后重启 DSH 服务使来源门控完整生效。

## 启动门控与包导出（`origin-bootstrap` 与主入口）

插件提供两个运行时入口，职责不同，不可混用：

1. **`@delthin/dsh-tool-wrap/origin-bootstrap`（来源门控适配器）**
   - 必须在宿主 `tools`、`system-prompt` 服务接纳依赖插件注册**之前**加载。
   - 观察工具与提示词段落注册时的真实 Loader 身份，分别提供 `toolDiscoveryOriginsReady`、`toolDiscoveryPromptOriginsReady`，保留原注册返回值、异常与生命周期。
2. **`@delthin/dsh-tool-wrap`（主插件入口）**
   - 提供 `unwrap` 工具注册、`tools:sdk` 提示词瀑布流（waterfall）精简、设置页 Web API 以及客户端界面。
   - 依赖 `toolDiscoveryOriginsReady` 建立加载顺序。

### 自定义启动组装（Composition / Patch）说明

- 标准启动补丁面向默认 `tools` 与 `system-prompt` entry，分别增加 `toolDiscoveryOriginsReady` 与 `toolDiscoveryPromptOriginsReady`。自定义 composition 已配置 `inject` 时，必须将原依赖与对应门控合并保留；后置 overlay 同样不能覆盖门控（宿主 patch 对 `inject` 为整体替换而非深合并）。
- 来源记录不能追溯观察器安装前已完成注册的工具或提示词。首次安装、升级此提示词来源门控或调整 `origin-bootstrap` 挂载顺序后，需要在获准的维护窗口重启并重新注册才能捕获完整来源；只刷新网页不能补记。设置保存本身对后续请求生效，无需重启。

## 使用方法

### 界面配置

启用插件后，可从 Web 界面左侧导航栏的「工具与提示词」（收起时位于「更多」菜单内）或「设置 → 工具与提示词」进入配置页：

1. 开启顶部总开关。
2. 在列表中勾选需要按需加载的插件，或点击插件行末箭头展开工具明细，按单个工具勾选或排除。
3. 点击底部「保存设置」。保存后立即作用于当前 profile 各会话的后续提示词组装，已接收且正在运行的请求不会被回溯修改。

界面合并工具与全部已知提示词来源，保留没有全局工具的来源。未记录来源的工具归入「未识别来源」，支持逐项勾选；未知归属的提示词单独显示，不根据名称猜测插件。

### 统一管理工具与提示词

列表按真实插件来源合并工具和提示词，同时列出 DSH 基础/persona、全局和项目 AGENTS、仅有提示词的插件及 unwrap 目录。可以调整整组顺序及组内贡献顺序，配置 `inherit/system/user` 角色与 `inherit/always/pack` 加载方式；逐源规则按字段覆盖组规则，`inherit` 继续继承组配置。当前适配不开放 developer 角色。

启用统一编排后，已包装插件的专属 section/context 默认随工具包返回；选 `always` 可保持常驻。解包成功且其父调用结果进入当前会话后，随包说明会在后续请求按配置进入真正的 system 或 user 消息。加载状态依据当前会话可见结果重建，重放可恢复，移除或回退该结果会取消加载；不影响其他会话。原生模式、无可调用 unwrap、完整 persona 未保留目录或来源没有可见延后工具时，指南仍常驻。unwrap 目录是独立贡献，不会隐藏自身。未知归属的动态贡献仍可排序和选择角色，但不能猜测归属或跟随某个工具包。

完整编排需要显式宿主适配：在完整 persona 恢复、动态上下文最终刷新之后、消息写入会话日志之前统一处理。普通用户对话不参与角色配置；结果照常记录为 system/user 消息及可重放的 surface 操作。AGENTS 在预算截断后提供逐文件结构边界，不重新读文件或按正文猜分块。来源目录只保留身份元数据，不保存提示词正文或会话 ID；动态来源在实际准入后出现。

独立配置为 `prompt-composition.json`：

```json
{ "version": 1, "enabled": false, "order": [], "rules": {} }
```

`order` 接受来源或组 ID；`rules[id]` 为 `{role:"inherit",delivery:"inherit"}`。已有 `prompt-order.json` v1 会迁移插件优先顺序并保留原文件，新编排默认关闭，等待确认。插件卸载后保留既有未知来源设置。接口 `GET/PUT /api/tool-discovery/prompt-composition` 返回配置、扁平来源记录和真实宿主能力；未支持的角色或加载方式会拒绝保存。它与工具配置独立，采用同源鉴权、64 KiB 限制及 0600 原子写入，不调用模型。

#### 显式宿主适配

适配资产和审核/恢复说明见 [host-support](<host-support/README.md>)。该脚本仅接受已审核 `0.2.2-rc.1` 的精确文件哈希和形态；包的最低版本开放范围保持不变。适配不是宿主既有公开 API，也不会在 npm 生命周期、插件加载或同步时自动执行。

```bash
node host-support/adapter.mjs --check --root <installation-root>
node host-support/adapter.mjs --apply --root <installation-root> --backup <backup-directory>
node host-support/adapter.mjs --restore --root <installation-root> --backup <backup-directory>
```

应用前须审核并授权，备份原文件；还原时只有当前文件仍匹配原始或适配哈希才会操作。脚本不重启服务、不修改运行 profile。未激活完整适配时仍展示全部已知来源和限制原因，统一编排不可启用。

### 模型端按需发现流程

在兼容的 PTC 会话中，当任务需要某个按需插件的能力时，模型会主动调用 `unwrap` 读取定义（无需用户在对话中手动提及“解包”或“发现”）：

1. **查看按需目录**（可选）：在 `run_code` 中执行 `return await tools.unwrap({});`，列出当前调用者可见的按需插件列表。
2. **按插件 ID 获取完整定义**：执行 `return await tools.unwrap({ plugin: "插件精确ID" });`，一次性获取该插件下所有对当前调用者可见的按需工具完整定义（含描述、参数与返回类型）。建议每次 `run_code` 仅加载一个插件包，避免多包叠加导致输出截断。
3. **获取未识别来源的单工具定义**：对于无插件归属的工具，执行 `return await tools.unwrap({ tool: "精确工具名" });`。
4. **正常调用工具**：在后续 `run_code` 步骤中直接调用 `tools.<name>(...)`。

返回值由宿主完整 JSON 序列化。如需打印，使用 `console.log(JSON.stringify(await tools.unwrap({plugin: "exact-plugin-id"})))`，不要直接 `console.log(object)`，避免 Node inspect 截断长 SDK；Python 使用 `json.dumps`。新旧入口都保留原有条件准入、scope、`toolSet` 与权限检查。

## 插件简介与默认模型生成

展开任意插件行即可查看或编辑该插件的简介说明：

- **优先级规则**：已保存的自定义简介优先于插件包内置的开发者说明。清空编辑框或点击「恢复开发者说明」并保存后，将删除自定义项并恢复使用开发者原始简介。
- **长度与数量限制**：最多支持保存 512 个插件的自定义简介；每条简介在去除首尾空白（trim）后长度须为 `1–2000` 字符。
- **AI 生成草稿**：当插件缺少说明或需要改写时，可点击「生成简介」。该操作仅调用当前部署的默认模型，向模型发送所选插件的全局工具名称与工具描述（**不发送**参数 schema、返回值 schema 或任何用户会话内容）。生成请求超时时间为 120 秒，可能会产生模型调用费用。生成结果仅作为草稿填入前端编辑框，需手动点击「保存设置」后才会写入配置文件；取消或生成失败不会破坏已保存设置，服务端错误信息均经过脱敏处理。

## 配置文件结构与迁移

配置保存在当前宿主 profile 目录下的 `tool-discovery.json` 中（无需也不应将真实运行配置复制到源码仓库）。

### 默认配置（Version 3）

```json
{
  "version": 3,
  "enabled": false,
  "groups": [],
  "tools": [],
  "exclude": [],
  "descriptions": {}
}
```

### 字段说明与约束

- `version`：固定为 `3`。新版设置页与保存接口要求 `v3` 格式。
- `enabled`：布尔值，控制是否启用按需发现与 SDK 精简。
- `groups`：字符串数组（上限 512 项），保存精确插件 ID。选中后该插件当前及未来新增的工具均纳入按需发现。
- `tools`：字符串数组（上限 512 项），保存显式指定纳入按需发现的工具精确名称。
- `exclude`：字符串数组（上限 512 项），保存显式排除的工具精确名称。**`exclude` 优先级最高**，其中的工具始终保留完整 SDK 展示，不进入折叠目录。
- **保留工具限制**：`run_code`、`unwrap` 与兼容名 `discover_tools` 不可放入 `tools` 或 `exclude`；按插件选择时也不会折叠这些保留入口。
- `descriptions`：键值映射对象（上限 512 项），键为精确插件 ID，值为自定义简介字符串（trim 后 `1–2000` 字符）。

### 版本迁移与文件安全

- **自动迁移**：读取旧版配置时，自动将 `v1` 的预设分组名（如 `browser`、`image`、`schedule`）及 `v2` 的不透明插件 ID 映射并统一升级为 `v3` 结构，保留原有的开关状态、`tools` 和 `exclude` 配置。
- **原子写入与权限**：保存配置时在同目录创建临时文件并执行原子 `rename`，文件权限设为 `0600`。
- **损坏保护**：若现有 `tool-discovery.json` 发生 JSON 语法损坏或结构非法，插件会显式报错并拒绝静默覆盖，防止意外丢失用户历史配置。

## 安全、权限与隔离边界

- **管理接口安全**：设置读写与简介生成 API 均受宿主认证与同源策略（Same-Origin）保护，请求体大小限制为 `64 KiB`。
- **不扩张执行权限**：工具发现和统一提示词编排不包装工具执行器，也不调用 `tools.restrict`。提示词角色变更只由已认证管理界面显式配置，并通过宿主准入适配执行；普通用户消息不会提升。`unwrap` 的输出严格从当前调用者的 `scope` 与宿主按步骤解析的 `toolSet` 交集中读取，完整保留条件工具准入、作用域覆盖（scoped shadow）、参数校验、审批流、guard、取消机制与沙箱限制。
- **会话级隔离**：定义作为工具结果返回当前对话。启用统一编排时，随包说明在成功解包后按当前会话的可见调用记录加载，并进入真实消息角色；不回写全局提示词，也不存在跨会话共享的“已解锁工具池”。其他会话的准入快照或已释放快照无法用于读取或执行工具。
- **保留动态上下文**：未启用统一编排时，图片供应商、画布等动态上下文保持原路径。启用后使用本步骤已刷新、已准入的内容，按配置常驻或随包加载；unwrap 不重新求值动态提供器。

## 性能观测与兼容回退

### SDK 投影字符观测

设置页提供「全局估算」与「最近组装」两类 SDK 投影字符对比（包含 SHA-256 截断摘要，不记录提示词正文、工具参数或会话 ID）：

- 页面展示的字符差值与粗估数值仅反映 **PTC SDK 投影字符数**的变化（已计入 `unwrap` 自身定义与概览目录的字符开销；仅勾选极少量短工具时，目录开销可能大于节省的字符数）。
- **重要说明**：SDK 投影字符数及摘要对比不等同于模型服务商的实际计费 token 数，也不能直接等同于真实的上下文缓存（Prompt Cache）命中率。固定配置与可见工具集时，SDK 确定性渲染；统一编排的角色、顺序调整和包说明激活仍可能改变系统文本与缓存前缀；但实际缓存命中与净收益请以模型路由返回的真实 usage / cache 统计为准。

### 自动回退场景

在以下任一情况下，插件会自动跳过业务工具精简并保留其完整定义；原文 SDK 精确匹配时仍隐藏兼容 alias：

1. 插件总开关处于关闭状态，或当前会话运行在原生（非 PTC）工具调用模式。
2. 当前调用上下文中 `unwrap` 不可见，或缺少 PTC `run_code` 传输支持。
3. 其他插件已先行改写 `tools:sdk` 文本导致结构不匹配（此时观测状态标记为 `incompatible-sdk`）。
4. 使用了会在 waterfall 组装后强制覆盖完整系统提示词的 preset（例如 `complete` persona）。

## 常见问题（FAQ）

### 1. 为什么安装或升级插件后，设置页里的工具全部显示在「未识别来源」下？
因为 `@delthin/dsh-tool-wrap/origin-bootstrap` 需要在宿主加载并注册各业务工具插件之前运行。如果仅热加载插件或只刷新了浏览器页面，启动前已注册的工具无法补记来源。请确认启动配置中已包含 `origin-bootstrap` 并**重启 DSH 服务**。

### 2. 开启插件后，正在进行的对话会立刻变成按需发现模式吗？
已在运行中的单次请求不会被回溯修改；保存设置后，该 profile 下各会话的后续提示词组装会按新配置生效。运行过程中模型调用 `unwrap` 不会修改 `tool-discovery.json` 配置文件。

### 3. 为什么勾选了某个插件，但其中某一个工具仍然完整出现在提示词里？
请检查该工具是否被加入了 `exclude`（排除列表）。`exclude` 的优先级高于 `groups` 和 `tools`，被排除的工具始终保持完整定义展示。

### 4. 简介生成会把我的聊天记录或私有配置发给大模型吗？
不会。点击「生成简介」时，服务端仅提取所选插件在全局目录中的插件名称、工具名称和工具简要说明发送给当前部署的默认模型，不包含任何对话历史、工具参数 schema 或返回值 schema。
