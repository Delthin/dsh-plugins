# @delthin/dsh-cardex

在任意 DSH 会话里记录一次讨论，结束时由整理模型把它拆成可独立查阅的 Markdown 知识卡片，维护最多三级的知识树，并生成离线 HTML 图谱。移植自 Pi 扩展 [`pi-cardex`](https://github.com/Delthin/pi-cardex)，沿用 `~/journal/cardex` 的 v2 数据格式，并支持读取 v1 索引。

[English](./README.en.md)

## 功能

- `/cardex 问题` 开始记录并直接提问；之后在该会话里的每一次追问都自动属于这次讨论。
- `/cardex end` 触发两次模型调用：先整理知识点（标题、范围简介、背景、正文、来源问答位置），再规划归档（匹配已有卡片、创建分组、维护三级树、补充语义关联）。
- 模型会判断新讨论与已有卡片的关联，并可将内容补充到已有卡片；不同归档批次按时间分段保留。
- 生成 `index.html`：离线阅读、树状导航、语义关联、卡片正文按归档批次分段；不依赖网络与外部资源。
- 支持中途取消、查看状态、只重建图谱、固定整理模型。

## 与 Pi 版的差异

旧版把"处理中提交的消息"退回到编辑框要求重发，并且必须手动结束记录。本版改为：

| 旧行为 | 现在 |
| --- | --- |
| `input` 拦截，忙时把消息吞回编辑框 | 不拦截任何消息；归档时从会话日志整段提取问答 |
| `/card 问题` 之后再手动 `/card end` | 同样需要 `end`，但随时可以继续追问，不会被阻塞 |
| `/card end 额外文字` 静默当普通问题 | 子命令带多余参数直接报错，并提示用 `/cardex --` 转义 |
| 归档失败要重新抓取会话内容 | 整理完成后、写入归档前冻结问答快照与记录 ID，重试复用快照 |
| 开始时可能多花一次检索调用 | 检索只作提示，失败不阻断开始记录 |

不使用 agent 预设：DSH 的预设只能在会话第一轮之前选定，切预设等于换一个会话、丢掉正在讨论的上下文。记录模式因此放在会话内部，用 `/cardex` 显式开启。

## 安装

```bash
npm install @delthin/dsh-cardex
```

启用后在会话输入框发送 `/cardex help` 即可确认可用。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/cardex 问题` | 开始记录这次讨论并发送问题 |
| `/cardex end` | 结束记录：整理知识卡片、归档、重建图谱 |
| `/cardex cancel` | 放弃本次记录（聊天内容保留） |
| `/cardex status` | 查看正在记录的内容、目录与整理模型 |
| `/cardex dir [路径]` | 查看或设置默认归档目录 |
| `/cardex model` / `follow` / `current` / `provider/model-id` | 查看或设置整理模型 |
| `/cardex graph` | 只重建离线图谱 |
| `/cardex help` | 命令列表 |
| `/cardex -- 问题` | 问题本身以命令词开头时转义 |

整理模型默认跟随当前会话模型；也可固定为某个 `provider/model-id`。整理调用不进入工具循环，只接受纯文本 JSON，超时默认 120 秒。

## 配置

设置文件默认 `$DSH_HOME/cardex.json`（未设置时为 `~/.dsh/cardex.json`），与旧版 `~/.pi/agent/pi-cardex.json` 同形：

```json
{
  "version": 1,
  "directory": "~/journal/cardex",
  "model": null,
  "timeoutMs": 120000
}
```

设置文件未提供 `directory` 时使用插件默认目录，未配置时为 `~/journal/cardex`；`model` 为 `null` 表示跟随当前会话。插件配置项 `directory` / `model` / `timeoutMs` 提供默认值，设置文件优先。修改这三个默认值会热更新：进行中的操作沿用开始时的配置，后续命令读取新值；已经开始记录的讨论仍写入原目录。`configPath` 指定设置文件位置，修改后插件重新加载。

## 数据

```
<directory>/
  index.json            知识树索引（version 2，兼容 v1 读取）
  index.html            离线阅读页与语义关联图谱
  cards/<id>.md         知识卡片，按归档批次分节
  discussions/<id>.md   原始问答，供卡片回链
```

写入使用临时文件 + `fsync` + `rename` 的原子替换，并带事务文件与锁文件；取得锁后，待处理的有效事务会在下次运行时重放。异常退出可能遗留 `.pi-cardex.lock`；确认没有进程正在写入该知识库后，手动移除锁文件，再重试。记录 ID 由草稿 id 与问答内容的 SHA-256 前 20 位组成，重复归档同一份问答不会产生第二份卡片。

## 安全边界

- 整理会将本次讨论发送给所选模型服务；归档规划和可选的知识目录检索还会发送已有目录的标题、简介及结构元数据。卡片、原始问答与图谱写入本地目录。
- 输入 JSON 明确标记为待处理数据，并提示忽略其中试图改变任务或输出格式的指令。
- 只有用户自己发送的消息进入归档；系统注入的调度、审批、标题等 user 角色消息被排除。
- 插件不含遥测；整理和可选的知识目录检索通过宿主调用所选模型服务，归档文件保存在本地。
- 离线图谱 HTML 内嵌卡片正文，可能包含原始问答；分享文件前请核对其中的内容。

## 常见问题

**归档很慢或失败？** `end` 是最花钱的一步（两次模型调用）。整理成功后会在写入归档前冻结问答快照；后续失败时再次执行 `/cardex end` 可复用该快照，已落盘的记录会报告已恢复。若整理阶段本身失败，重试会重新读取当时的会话。

**一个会话能记录几次讨论？** 一次。结束或取消后可以在同一会话再次 `/cardex 问题` 开始新的讨论。

**卡片里没出现某条回答？** 只归档 `end` 之前的问答；最后一个还没回答完的问题会被要求等回答结束。
