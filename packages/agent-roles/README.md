# DSH Agent Roles

[English](README.en.md) · [发布记录](CHANGELOG.md) · [发布指南](docs/RELEASING.md)

为 **DeepSeek Harness Web 0.2.1-rc.5+** 提供角色管理界面，并基于 DSH 原生 Agent Team 接口创建角色成员、分发任务和继续对话。

在本插件中，**角色（Role）**是可复用的配置模板，用于保存职责提示词、模型与思考强度、工具白名单及 Skills；**成员（Member）**是由主代理按角色启动的具体运行实例。主代理在会话中能够看到所有已启用角色的职责、模型和已选 Skills，并根据当前任务判断何时调用 `spawn_role` 创建成员，无需预设固定工作流。

## 安装

环境要求：Node.js 22.18+、DSH Web **0.2.1-rc.5 及以上**，以及至少一个已配置的模型供应商。宿主及 DSH 依赖使用最低版本约束，不再锁定单个版本；底层 Agent Team 接口仍处于实验阶段。

通过 GitHub Release 归档安装 `v0.4.0`：

```sh
dsh plugin --profile web add https://github.com/Delthin/dsh-agent-roles/releases/download/v0.4.0/dsh-agent-roles-0.4.0.tgz
```

如对应版本已在 npm 发布，也可执行 `dsh plugin --profile web add dsh-agent-roles@0.4.0`。可通过 `npm view dsh-agent-roles@0.4.0 version` 核对 npm 可用性；若尚不可用，使用上面的 GitHub Release 地址。插件市场收录独立于这两种安装方式。

安装过程无需编译，也不会执行安装脚本。安装后刷新 DSH Web 页面即可在左侧导航栏看到「多智能体」入口；若宿主未自动加载，请重启对应的 Web profile。

首次安装提供**空角色目录**，不包含作者的角色、提示词、模型配置或运行记录；升级已有安装则会保留本地数据。插件 bundle 会启用 DSH 原生团队服务、团队工具与界面，并停用旧的 `tool-subagent`、`tool-subagent-fork`、`tool-subagent-control`、`tool-subagent-list-agents` 条目，切换方式与官方实验团队 profile 一致。若当前环境已有自定义团队 bundle，请检查是否存在相同 ID 的配置覆盖。

## 配置角色与分发任务

### 1. 创建角色

1. 在左侧打开「多智能体 → 角色 → 新增角色」。
2. 填写显示名称、分发名称（小写字母、数字和连字符，如 `reviewer`）及职责描述。职责描述将供主代理判断何时选用该角色。
3. 选择该角色使用的模型供应商、具体模型和思考强度。
4. 在「提示词」中定义角色职责、工作边界和交付标准；在「工具」中仅勾选该角色必需的工具白名单。
5. 在「技能」中按需搜索并勾选 DSH 已发现的 Skills（默认为空，不自动继承全局技能目录）。
6. 将角色设为启用并保存。

### 2. 任务分发与协作机制

角色启用后，直接在主会话向主代理描述任务即可。例如配置了只读审阅角色 `reviewer` 后，可以对主代理说：

> 请把这份改动交给 reviewer 审阅，要求指出有依据的问题；你汇总结果并决定如何处理。

运行与协作规则如下：

- **按需创建实例**：主代理调用 `spawn_role({role, name, prompt})` 启动成员，底层通过原生 `agentTeams.spawnTeammate` 创建实例。成员启动时会保存当时的角色提示词、模型设置和 Skills 正文快照，后续修改或删除角色不会影响已创建的成员。
- **独立会话与多轮沟通**：新成员在独立的全新（fresh）会话中启动，不继承主代理的上下文历史，因此主代理在分发任务时需在 `prompt` 中提供必要背景与材料。需要追问或补充材料时，主代理可通过原生 `send_message` 继续与同一成员实例沟通。
- **集中协调**：成员的工具白名单不包含递归委派工具，成员之间也不能相互主动通信；所有任务拆解、结果汇总与跨成员协调均由主代理负责，并通过 `list_agents`、`send_message`、`interrupt_agent`、`wait_agent` 管理。其中 `list_agents` 查询的是当前已创建的成员实例，而非角色目录。
- **状态与结果查看**：可在主会话顶部的子智能体/团队入口进入成员原生会话，或在「多智能体 → 子智能体」列表中查看该数据目录最近的角色成员记录、展开输出摘要或点击「会话」跳转。成员状态显示为 `inactive` 仅代表当前没有正在执行的回合，不代表任务已成功完成，具体结论或错误需结合成员输出内容判断。
- **请求校验**：在成员记录的「请求详情」中，插件会根据实际发出的请求记录所用模型、思考强度与工具列表，并核对 DSH 基础系统提示词、角色提示词原文及所选技能正文是否完整加载（`0.2.1-rc.5` 原生成员列表的模型字段可能保留父会话描述，实际路由以「请求详情」为准）。

### 3. Skills 加载与沟通成本

新建和已有角色默认 `skills: []`。勾选 Skills 后，插件在启动成员时通过 DSH 原生技能服务读取对应内容，并以原生 `<skill_content>` 格式（含资源基目录与字面正文）完整注入新成员的系统提示词；即使是不勾选任何工具的角色，也能接收所选 Skills 的指令。

Skills 仅提供文本指令，不会自动赋予工具权限，技能所需的外部命令、软件或依赖仍需在宿主和工具白名单中另行配置。若所选技能在启动时不可用，成员启动将直接失败并报告缺失的技能名称，恢复技能或取消勾选后即可重试。

额外沟通成本主要来自主代理和成员处理任务、结果与追问时的模型输入输出；勾选的 Skills 完整正文也会计入成员会话输入。建议只为角色勾选必要的 Skills，对于简单直接的任务由主代理直接完成即可，无需拆分为多智能体协作。

## 数据存储与配置

默认数据目录为 `$DSH_HOME/agent-roles`（未设置 `DSH_HOME` 时为 `~/.dsh/agent-roles`）：

- `roles.json`：保存角色目录、结构版本号和目录修订号。
- `runs.json`：保存成员启动快照、所选技能正文、请求加载校验结果，以及最多 30,000 字符的最近输出摘要。完整对话历史仍由 DSH 原生会话存储保存。

如需自定义数据目录或启用可选的供应商 Fast 开关，可在当前 profile 的 `cordis.patch.yml` 中配置：

```yaml
- id: agent-roles
  config:
    dataDir: ~/my-dsh-data/agent-roles
    fastProviders: []
```

`dataDir` 支持绝对路径、`~` 以及相对于当前进程工作目录的路径（建议使用绝对路径）。当前文件存储不提供跨进程写锁，多个独立运行的 DSH 进程应配置不同的 `dataDir`。

公开包默认 `fastProviders: []`，模型选择器旁的 Fast 按钮不可启用。本插件仅在角色与成员快照中记录 Fast/标准模式选择，不内置特定模型供应商的 priority 传输实现；仅当环境中已安装对应的传输适配且能读取角色启动快照时，才应将供应商 ID 加入 `fastProviders`。启用 priority 传输可能改变供应商侧的计费标准。

### 限制主代理可委派的模型

在 **多智能体 → 设置** 中添加规则：选择主代理模型，勾选禁止的子代理模型，保存后立即生效。模型选项来自 DSH 已配置目录；默认没有规则，不限制委派。配置通过 DSH 原生配置服务写入当前 profile，并检测并发修改。

也可直接设置通用的 `delegationRules`，如下列示例 ID（请替换成自己的模型 ID）：

```yaml
- id: agent-roles
  config:
    delegationRules:
      - leaderModel: lead-model-id
        denyModels:
          - blocked-member-model-id
```

模型 ID 精确匹配，不区分供应商。策略按主代理当前请求的模型执行，切换模型后下一轮随之变化；角色目录隐藏禁止的角色，工具调用在启动前拒绝。受限制主代理必须使用 `spawn_role`，通用委派工具也会被拦截；向已有禁止模型成员发送消息同样拒绝。已经运行的成员不会被自动中断。

## 运行限制与安全边界

- **原生配额与委派深度**：单个团队最多支持 32 个已创建成员和 256 个共享任务。并发数与委派深度受 DSH 原生 subagent 配置约束；若宿主将委派深度设为 `0`，需先在宿主配置中允许委派。本插件不会越权修改全局配额或系统权限。
- **实现机制与接口认证**：插件通过原生 `agent/created` 钩子在成员首个请求发出前挂载模型路由、系统提示词与工具白名单守卫，不接管或替换 DSH 原生模型执行循环。角色管理 API 复用 DSH Web 连接服务的身份验证，拒绝未认证请求。
- **权限与安全边界**：角色工具白名单仅约束模型可调用的工具集，并非操作系统级文件或目录沙箱；具体文件读写与命令执行仍受 DSH 全局权限与文件策略控制。角色提示词和 Skills 是提供给模型的受信任指令；插件代码运行在宿主进程权限下。请勿将同一个已登录的 DSH Web 会话暴露给不可信用户。
- **数据生命周期**：`runs.json` 中的成员快照包含提示词、技能全文和输出摘要，备份时请按私人敏感数据妥善保护。卸载插件不会自动删除数据目录，删除角色也不会清理已生成的成员运行记录。运行记录目前不自动过期，列表 API 默认返回最近 200 条记录。

## 开发与校验

```sh
git clone https://github.com/Delthin/dsh-agent-roles.git
cd dsh-agent-roles
npm ci --ignore-scripts
npm run check
npm test
npm run release:check
```

仓库服务端与客户端均直接分发 JavaScript 源码，无编译构建步骤；前端界面直接使用 DSH Web 内置的 React 与原生 UI 组件。测试套件使用虚构角色与模拟模型，不调用外部付费模型接口。

发布前检查、隐私检查、npm/GitHub Release 流程及市场收录说明见 [发布指南](docs/RELEASING.md)。提交问题报告时请附上 DSH 版本、插件版本及脱敏后的错误日志，切勿上传私有角色配置、访问令牌或完整会话数据。
